## 3. 需要你先决策的两件事

### 3.1 QMS 修复会改变对外契约 —— 要不要同步改前端？

已核实：`QmsDocumentForm.vue` 把 `status` 当普通表单字段提交（`<el-form-item label="状态">` + `el-input-number`）。
服务端现在忽略它，于是**前端那个输入框会静默失效**（用户填了不报错，但也不生效）。

三个选项，**我倾向 B**：

- **A**：只改服务端，前端留着死字段 —— 用户会被静默欺骗，最差。
- **B**：把 QMS 这些表单/列表里的"状态"字段改成**只读回显**，并补 `<dict-tag>` 渲染
  （顺带解决 §12.235.5 记录的"QMS 状态字典没有走 Flyway、前端 0 处用 dict-tag、34 处直接显示裸整数"）。
- **C**：前端删除该字段 —— 改动最小，但列表里就看不出状态了。

### 3.2 QMS 状态字典要不要补进 Flyway？

已核实（对沙箱库实测）：`qms_doc_status`、`qms_doc_type`、`qms_nc_status` 等 **6 个 QMS 字典
在库里 type/data 计数全为 0**，只存在于未部署的 `sql/mysql/*.sql`。
前端 `DICT_TYPE` 里 QMS 常量数也是 **0**（对照 CRM 11、MES 72）。

若采纳 3.1 的选项 B，这一条必须一起做，否则 `<dict-tag>` 渲染不出来。
