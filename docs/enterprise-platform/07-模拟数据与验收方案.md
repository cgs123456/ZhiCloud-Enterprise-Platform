# 07 模拟数据与验收方案

> 本方案面向无真实数据的开发、演示、测试和沙箱环境。
> **所有模拟数据禁止导入生产。**

## 1. 当前状态

当前 `demo-data/` 的仓库原始内容只有 8 套数据库方言的演示账号 SQL，内容主要是 `system_users` 演示账号，不包含完整的 ERP/MES/WMS/QMS/CRM/HR/OA/TMS 业务场景数据。

因此**仅凭仓库原有内容**还不能用 `demo-data/` 做端到端业务验收。

### 1.2 交付边界（必须写在验收结论之前）

1. **STATIC_ONLY**：以上 SQL / JSON **从未在任何数据库实例上执行过**。当前环境 Docker 不可用，无法起库，因此「能否导入成功」「约束是否冲突」「导入耗时」**全部未验证**。生成器只保证静态层面自洽（列取自快照、NOT NULL 全覆盖、枚举符合快照与迁移脚本中的取值、唯一键不重复）。
2. **仅 MySQL**：dm / highgo / kingbase / opengauss / oracle / postgresql / sqlserver 七套方言的模拟数据未生成（`b'0'` 这类 BIT 字面量只在 MySQL 有效，跨方言必须重做）。
3. **仅主数据**：`scenarios/01`–`06` 所需的业务单据（销售订单、采购订单、库存流水、工单、检验单、运单、会计凭证……）**一条都没有生成**，因此 §6 的六条端到端场景**无法验收**。
4. **量级远低于 §5.1 建议**（small 档）：

| §5.1 对象 | 建议数量 | 已交付（small / large） | 差距 |
|---|---:|---:|---|
| 租户 | 2-3 | 1（可 `--tenant` 生成多个） | 脚本支持，未批量生成 |
| 组织/部门 | 20-50 | 8 / 40 | large 档达标 |
| 人员 | 200-1000 | 40 / 200 | large 档下限达标 |
| 物料 | 500-2000 | 24 / 480 | large 档接近下限，未达标 |
| 供应商 | 50-200 | 10 / 100 | large 档达标 |
| 客户 | 100-500 | 12（ERP）+15（CRM）/ 120+150 | large 档下限达标 |
| 仓库/库区/库位 | 3/5/100 | 4/12/48 → large 20/60/240 | large 档达标 |
| BOM / 工艺路线 / 科目 / 成本中心 | 100-500 等 | **0** | 未覆盖 |

5. **7 个字段刻意留 NULL**（不做猜测，见 manifest `unverified_fields`）：`crm_customer.source/industry_id/area_id/owner_user_id`、`tms_vehicle.driver_user_id`、`hr_employee.id_card`、`hr_department.leader_id`。
6. **MES / QMS / OA 三域零覆盖**：这三个域的主数据（工艺路线、工作中心、设备、检验项、审批流等）尚未建模到生成器。

## 2. 环境边界

| 环境 | 是否允许模拟数据 | 说明 |

## 4. 数据隔离规则

- 使用独立数据库或独立 schema。
- 使用专用租户，例如 `tenant_id=9001` 起。
- 所有账号、单据、物料、客户名称带 `DEMO_` 前缀。
- 不使用真实手机号、身份证号、邮箱、银行卡、地址。
- 不使用生产 Secret、生产域名、生产对象存储桶。
- 所有生成脚本使用固定随机种子，保证可重复。
- 所有插入必须幂等或支持先清理再生成。

## 5. 数据集设计

### 5.1 主数据

| 对象 | 建议数量 | 说明 |
|---|---:|---|
| 租户 | 2-3 | 一个主租户，一个隔离验证租户 |
| 组织/部门 | 20-50 | 多层级 |
| 人员 | 200-1000 | 无真实个人信息 |
| 物料 | 500-2000 | 原材料、半成品、成品、包装 |
| BOM | 100-500 | 多层 BOM |
| 供应商 | 50-200 | 多评级、多账期 |
| 客户 | 100-500 | 多区域、多信用等级 |
| 工厂/仓库/库位 | 3/5/100 | 支持多仓多库位 |
| 科目/成本中心 | 100/30 | 财务核算 |

### 5.2 ERP

- 采购申请、采购订单、收货、应付、付款。
- 销售报价、销售订单、发货、应收、收款。
- 库存余额、库存流水、盘点、调拨。
- 总账、凭证、期间、预算、成本、资产。

建议规模：

```text

销售订单 1000-5000
库存流水 10000-100000

```

### 5.3 MES

- 物料、BOM、工艺路线、工作中心、设备。
- 生产计划、工单、派工、报工、发料、完工、返工。
- 设备点检、保养、故障、停机、OEE。

建议规模：

```text
工单 500-3000
报工记录 5000-30000
设备 50-300
工序记录 10000-50000
```

### 5.4 WMS

- 收货单、上架、库存、批次、SN、库位。
- 出库单、波次、拣货、复核、包装、发运。
- 盘点、调拨、冻结、释放、3PL 计费。

建议规模：

```text
库存行 5000-50000
入库单 500-3000
出库单 1000-5000
库存流水 20000-200000
```

### 5.5 QMS

- IQC/IPQC/OQC 检验单。
- NCR、CAPA、8D、FMEA、SPC、MSA。
- 仪器、校准、电子签名。

必须包含：

- 合格批次。
- 不合格批次。
- CRITICAL 缺陷一票否决场景。
- 超期、复检、返工、让步接收场景。

### 5.6 CRM / HR / OA / TMS

- CRM：线索、商机、合同、回款、服务工单。
- HR：员工、组织、考勤、薪酬、绩效、招聘。
- OA：审批、公文、会议、知识库、公告、日程。
- TMS：承运商、车辆、司机、运单、GPS、运费、对账。

## 6. 六条验收场景

### 场景 1：线索到回款

1. 创建线索。
2. 转商机。
3. 生成报价和合同。
4. 生成销售订单。
5. 库存预占和出库。
6. 开票和回款。
7. 验证合同、订单、出库、应收、回款一致。

### 场景 2：采购到付款

1. 请购。
2. 采购订单。
3. 收货。
4. IQC 检验。
5. 入库。
6. 应付。
7. 付款。
8. 验证不合格不能入库。

### 场景 3：计划到生产

1. 销售需求。
2. MPS/MRP。
3. 生产工单。
4. 发料。
5. 报工。
6. 完工入库。
7. OQC。
8. 验证超产、超发料被拒绝。

### 场景 4：订单到交付

1. 销售订单。
2. WMS 库存预占。
3. 波次拣货。
4. 复核包装。
5. 发运。
6. TMS 运单。
7. 签收回单。
8. 验证库存、运单、应收一致。

### 场景 5：问题到解决

1. 客户投诉。
2. 创建 NCR。
3. CAPA/8D。
4. 退货或索赔。
5. 财务处理。
6. 验证闭环和审计。

### 场景 6：入职到离职

1. 招聘。
2. 入职。
3. 权限开通。
4. 考勤和薪酬。
5. 调岗。
6. 离职。
7. 权限回收。
8. 验证敏感数据权限。

## 7. 数据不变量

模拟数据生成后必须验证：

- 同一租户内业务编码唯一。
- 跨租户不能读取对方数据。
- 库存 `available + locked + frozen <= quantity`（按业务定义调整）。
- 出库数量不超过可用量。
- 报工累计不超过工单数量。
- 发料累计不超过 BOM 应发量。
- 质检不合格不能入库/发运。
- 合同回款不超过合同额。
- 会计凭证借贷平衡。
- 事件幂等键唯一。
- 删除/归档后向量、文件、业务记录一致。

## 8. 生成与清理

### 生成

- 使用固定种子。
- 支持 `--tenant`、`--scenario`、`--scale`。
- 生成后输出 manifest：版本、时间、租户、数据量、校验和。
- 禁止输出真实个人信息。

### 清理

- 只清理指定 DEMO 租户。
- 先备份 manifest 和校验结果。
- 清理顺序遵循外键和事件依赖。
- 清理后执行残留检查。

## 9. 验收证据

每个场景必须输出：

- 执行步骤。
- 输入数据 manifest。
- 关键接口/SQL 输出。
- 不变量检查结果。
- 失败和未覆盖项。
- 执行人和时间。

## 10. 结论

模拟数据的价值不是“页面好看”，而是：

> **在没有真实数据的前提下，仍能验证业务闭环、并发正确性、租户隔离、幂等、对账和审计。**

按这个标准衡量，本轮交付**只完成了前置条件的一半**：主数据这一层已经可复现、可隔离、可清理，
但真正体现业务闭环的**六条端到端场景（§6）一条都还没验收**，且所有产物都未进过真实数据库。
因此本文 §9 要求的「执行步骤 / 输入 manifest / 关键输出 / 不变量检查 / 失败与未覆盖项」五类证据
**目前一份都拿不出来**——在补齐业务单据生成器并拥有可执行的数据库实例之前，
任何“模拟数据已完成”的表述都是不成立的。
