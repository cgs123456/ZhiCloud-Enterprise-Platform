### 2.2 TLS 与网络

- MySQL：`sslMode=VERIFY_IDENTITY` 只是配置，必须完成真实握手、证书链和主机名验证。
- PostgreSQL：`sslmode=verify-full` 只是配置，必须完成真实握手和证书链验证。
- Redis、消息、对象存储：按生产网络边界定义 TLS 和认证。
- 管理端口 48090：必须用 NetworkPolicy/安全组限制来源。

## 5. 证据要求

每条门禁通过必须同时具备：

1. 当前 commit SHA。
2. 执行命令或操作步骤。
3. 原始输出/报告路径。
4. 执行时间和环境。
5. 失败项和未覆盖项。
6. 复核人。

**没有证据的能力，只能标记为“待验证”。**

## 6. 当前禁止事项

- 禁止用假 Secret 消除 P0。
- 禁止放宽扫描规则或修改断言制造“通过”。
- 禁止把静态检查写成真实 TLS 验证。
- 禁止把 bootstrap 静态契约或 Helm 渲染成功写成目标数据库执行通过。
- 禁止把 V116/V117 的 clean 沙箱迁移或 100,000 行合成 DDL 证据写成生产迁移、生产规模 MDL/复制验证或生产就绪。
- 禁止把沙箱迁移写成生产迁移。
- 禁止把 Maven BUILD SUCCESS 写成生产可部署。
- 禁止把模拟数据导入生产。
