- 轮换 Secret 不等于修复代码；旧 Secret 必须在供应商侧失效，客户端配置必须改为外部注入。

建议修复顺序：

1. 盘点客户端、供应商、环境、负责人和调用方。
2. 在供应商和授权服务器侧创建新 Secret，执行双密钥过渡。
3. 禁用或删除演示客户端，保留审计记录。
4. 修改安装脚本和 bootstrap 流程，只保留外部注入占位，不写入真实值。
5. 验证旧 Secret 被拒绝，再撤销旧值。
6. 重新扫描并确认 R10 为 0。
