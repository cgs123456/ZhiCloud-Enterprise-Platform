# 09 实施排期与资源估算

> 本文是规划估算，不是工期承诺。实际周期受真实基础设施、业务专家、合规范围、数据量和团队熟练度影响。

## 1. 两种交付口径

### 口径 A：单租户/有限范围的“可生产最小版本”

适合先上线一个事业部或一个工厂，范围包括：

- ERP 采购、销售、库存、基础财务。
- WMS 收货、上架、拣货、复核、发运、盘点。
- MES 工单、报工、发料、完工、基础质量。
- QMS IQC/IPQC/OQC 和门禁。
- CRM 合同、回款。
- 基础 HR/OA/TMS 或暂缓。

估算：

| 资源 | 数量 |
|---|---:|
| 架构/技术负责人 | 1 |
| 后端 | 3-4 |
| 前端 | 1-2 |
| 测试/QA | 1-2 |
| DevOps/SRE | 1 |
| 安全/合规 | 0.5 |
| DBA | 0.5 |
| 产品/业务分析 | 1 |
| 合计 | 7-10 FTE |

周期：**6-9 个月**（含 30%-50% 风险缓冲）。

### 口径 B：完整多租户、多组织、八域大型平台

范围包括：

- 八域完整闭环。
- 多组织、多工厂、多仓库、多币种。
- SSO/MFA、审计、等保/行业合规。
- 数据仓库、BI、AI。
- 高可用、灾备、SLO、on-call。
- SRM/EAM/PLM 等新增域。

估算：

| 资源 | 数量 |
|---|---:|
| 架构/技术负责人 | 1-2 |
| 后端 | 6-10 |
| 前端 | 3-5 |
| 测试/QA | 2-4 |
| DevOps/SRE | 2-3 |
| 安全/合规 | 1-2 |
| DBA/数据 | 1-2 |
| 产品/业务分析 | 2-4 |
| 合计 | 18-32 FTE |

周期：**18-30 个月**，并需要真实业务专家持续参与。

### 口径 C：个人开发者

如果只有 1 人：

- 可生产最小版本：**18-36 个月**。
- 完整平台：**5-10 年以上**，且质量、合规和运维风险很高。

建议不要用个人项目周期去承诺企业级交付。

## 2. 阶段划分

### M0：审计与冻结（2-4 周）

- 确认当前 commit、迁移、环境。
- 建立证据目录。
- 冻结 schema 和发布窗口。
- 盘点 Secret、账号、数据、集成点。

### M1：生产安全底座（4-8 周）

- Secret 管理。
- 种子账号清理。
- 客户端 Secret 轮换。
- TLS、K8s dry-run、备份恢复。
- 租户隔离回归。

**退出：** G1 通过，G4 至少完成 dry-run。

### M2：核心业务正确性（8-16 周）

- 库存单一真值。
- QMS 门禁。
- MES 状态机。
- WMS 流程闭环。
- CRM 回款幂等。
- ERP 过账和对账。

**退出：** G2/G3 核心链路通过。

### M3：平台化与可观测性（8-16 周）

- 全模块 `api` 包。
- 事件契约、DLQ、重放、补偿。
- SLO、告警、追踪、on-call。
- 数据治理和指标口径。

**退出：** G3/G5 通过。

### M4：生产演练与上线（4-8 周）

- 预发全量回归。
- 压测、长稳、故障注入。
- 备份恢复、灾备。
- 金丝雀和回滚演练。
- 上线评审。

**退出：** G0-G8 全部通过。

### M5：持续演进（长期）

- SRM/EAM/PLM/BI。
- IoT/CDP/ESG（按需求）。
- 多组织、多币种、多语言。
- 成本、性能和体验优化。

## 3. 依赖关系

| 依赖 | 影响 |
|---|---|
| 真实基础设施 | TLS、K8s、备份、灾备无法完成 |
| 密钥管理系统 | Secret 轮换和 fail-closed 无法闭环 |
| 业务专家 | 状态机、财务、质量规则无法确认 |
| 合规范围 | 等保/个保法/行业要求无法定级 |
| DBA | 大表迁移、索引、备份恢复无法保障 |
| SRE | SLO、告警、on-call 无法落地 |
| 测试环境 | 端到端和并发测试无法可信 |
| 数据量基线 | 性能和容量无法验证 |

## 4. 成本变量

除人力外，必须预算：

- 数据库高可用、备份、存储和带宽。
- Redis、消息、对象存储、可观测性组件。
- KMS/Vault/云 Secret Manager。
- 日志、指标、追踪的存储成本。
- 安全扫描、渗透测试、合规审计。
- 灾备环境和跨区域流量。
- 证书、域名、WAF、CDN。
- AI 模型、向量库和 GPU/推理成本（如启用）。

**容易漏掉的成本：** 迁移停机窗口、双写期间资源、数据清洗人力、业务培训、上线后 2-4 周的强化值守。

## 5. 里程碑建议

| 里程碑 | 目标 | 预计周期 |
|---|---|---:|
| M0 | 审计完成、证据基线 | 2-4 周 |
| M1 | 安全底座可用 | 4-8 周 |
| M2 | 核心业务闭环 | 8-16 周 |
| M3 | 平台化和可观测 | 8-16 周 |
| M4 | 生产演练和上线 | 4-8 周 |
| M5 | 持续演进 | 长期 |

## 6. 风险缓冲

建议所有阶段预留：

- 30% 常规风险缓冲。
- 数据迁移、合规、真实环境接入额外 30%-50% 缓冲。
- 关键人员不足时，不得压缩测试、备份、安全审计和灾备。

## 7. 结论

- **不要承诺“一周内可生产上线”。**
- 单租户有限范围可生产版本，现实周期为 6-9 个月、7-10 人。
- 完整大型平台是多年工程，不是一次升级任务。
- 如果只有个人开发者，应把目标改为“可演示、可验证的 MVP”，而不是直接承诺企业级生产交付。
