# 04 业务模块升级路线

> 本文只定义业务能力目标、优先级和验收口径，不把尚未实现的能力写成已完成。

## 1. 跨域主流程

优先打通六条主流程：

| 主流程 | 关键域 | 最小闭环 |
|---|---|---|
| 线索到回款 | CRM -> ERP | 线索、商机、合同、订单、发货、开票、回款 |
| 采购到付款 | ERP -> WMS -> QMS | 请购、采购、收货、质检、入库、应付、付款 |
| 计划到生产 | ERP -> MES -> WMS -> QMS | 需求、MPS/MRP、工单、发料、报工、完工、检验 |
| 订单到交付 | CRM/ERP -> WMS -> TMS | 销售订单、库存预占、拣货、复核、发运、运单 |
| 问题到解决 | QMS/CRM -> ERP | 客诉、NCR、CAPA、8D、退货、索赔 |
| 入职到离职 | HR -> OA -> ERP | 招聘、入职、考勤、薪酬、权限、离职 |

## 2. ERP

### 当前基础

- 总账、凭证、账套、资产负债表、现金流量表、合并引擎。
- 采购、销售、库存、成本、资产、税务、资金、外币。
- V99 起已有会计事件勾稽总额和超额过账守卫。
- V110 起补充成本、MPS 相关表。

### P0

1. 库存数量以 WMS 为唯一权威来源，ERP 改财务/成本投影。
2. 所有金额、数量、比例使用 BigDecimal；禁止 `equals` 比较精度。
3. 入库、出库、盘点、调整数量必须校验正负数和可用量。
4. 过账、冲销、期间关闭必须幂等、可审计、可追溯。
5. 业务单据到会计事件到凭证必须有对账入口。
6. 负库存策略必须显式配置，不能留下硬编码占位实现。

### P1

- 成本：移动加权、标准成本、差异分析、期末结转。
- 应收/应付账龄、信用额度、坏账、税务发票。
- 预算、资金计划、合并报表、多币种折算。
- 采购到付款、销售到收款的端到端对账。

### P2

- 多组织、多账套、多准则、多币种。
- 税务合规适配、电子发票、银行对账。
- 经营驾驶舱和异常预警。

### 验收指标

- 库存账实差异率低于业务阈值，并有日终差异报表。
- 所有凭证可由业务单据反查。
- 过账重复请求不会重复记账。
- 采购到付款、销售到收款全链路可回放。

## 3. MES

### 当前基础

- 148 个 Controller，覆盖排产、设备、主数据、生产、质量、工具、仓储、能源。
- 已有 APS/MRP、Andon、OEE、SCADA、PDA 报工、替代料等能力描述。
- V111 增加 TPM 和返工表。

### P0

1. 工单状态机完整：`CREATED -> CONFIRMED -> DISPATCHED -> REPORTING -> FINISHED -> CLOSED`，禁止跳级和死锁。
2. 报工累计量使用数据库 CAS，不能超过工单数量。
3. 发料累计量不能超过 BOM 应发量，超领必须有审批。
4. 质量放行作为工序流转前置条件。
5. SQL 拼接 BigDecimal 改为参数化 SQL。
6. 设备、工单、工序、批次、人员建立可追溯关系。

### P1

- APS 排产约束：设备、模具、人员、换型、交期、物料。
- OEE、停机、节拍、良率、能耗。
- OPC-UA/SCADA 设备接入和边缘网关。
- 返工、拆解、替代料、联副产品。

### P2

- 数字孪生、预测性维护、能耗优化。
- 多工厂、多车间、多产线协同。

### 验收指标

- 工单状态非法跃迁全部被拒绝。
- 超产、超发料在并发下仍被拒绝。
- 工单到报工到完工入库可追溯。
- 质量不合格不能继续流转。

## 4. WMS

### 当前基础

- 38 个 Controller，覆盖 FEFO、SN、3PL 计费、越库、ABC、PDA、波次、安全库存。
- V109 增加发运单租户唯一约束。

### P0

1. 禁止从 `PREPARE` 直接跳到 `FINISHED` 并扣库存。
2. 出库必须经过拣货、复核、包装、发运；测试环境才允许旁路且必须显式开关和审计。
3. 盘点同时更新 `quantity` 和 `availableQuantity`，并生成差异流水。
4. 创建/拣货阶段预占库存，取消和失败释放预占。
5. 所有库存变更必须有幂等键和库存流水。
6. 收货必须校验 QMS IQC 放行状态。

### P1

- 上架策略、波次策略、拣货路径、播种式/摘果式。
- 批次、效期、序列号、FEFO/FIFO/LIFO。
- 3PL 计费、库容、月台、越库、自动补货。
- 库存对账和差异处理工作台。

### P2

- 自动化立体库、AGV/AMR、数字拣选。
- 多仓、多货主、多组织库存网络。

### 验收指标

- 出库流程不可绕过复核。
- 可用量、锁定量、冻结量、实存量关系恒成立。
- 盘点差异可追溯。
- 库存日终对账差异可解释。

## 5. QMS

### 当前基础

- IQC/IPQC/OQC、FMEA、8D、CAPA、SPC、MSA、NCR、SCAR、追溯、电子签名。
- V112 增加文档、审计、仪器相关表。

### P0

1. 用 AQL/Ac/Re 和明确缺陷分级替代 `failRate > 0.5` 这类错误判定。
2. CRITICAL 缺陷一票否决。
3. 提供 `qms/api` 的放行查询，WMS/MES 收货和流转必须调用。
4. 检验单必须有幂等键和事务边界。
5. 不合格品必须进入 NCR/CAPA，不能只改状态。
6. 电子签名记录完整审计信息。

### P1

- SPC 控制图、过程能力、MSA、FMEA 版本。
- CAPA 闭环、有效性验证、供应商 SCAR。
- 质量成本、供应商质量绩效。
- 仪器校准和有效期管理。

### P2

- 法规包：IATF 16949、GMP、21 CFR Part 11、ISO 13485。
- 质量数据湖和预测分析。

### 验收指标

- 质检不合格无法入库/流转/发运。
- 判定规则可配置、可测试、可审计。
- 检验单重复提交不会重复扣分或重复生成任务。

## 6. CRM

### 当前基础

- 客户、线索、商机、合同、回款、公海池、数据权限、电子签。
- 已有合同回款链路，但需要并发和幂等加固。

### P0

1. 回款累计额不能超过合同额，使用数据库 CAS 或锁。
2. 回款、退款、合同变更必须有幂等键。
3. 客户、联系人、商机、合同的租户和数据权限必须回归测试。
4. 合同状态和金额变更必须审计。

### P1

- 服务工单、SLA、客户 360、CPQ、报价审批。
- 销售预测、渠道、伙伴、营销活动。
- 合同到订单到回款到开票的闭环。

### P2

- CDP、客户分层、流失预测。
- 多渠道协同和智能推荐。

### 验收指标

- 并发回款不超合同额。
- 重复提交不重复入账。
- 合同、订单、回款、发票可互相追溯。

## 7. HR

### 当前基础

- 组织、员工、考勤、薪酬、绩效、合同、社保、招聘。
- 测试和合规证据偏弱。

### P0

1. 员工、薪酬、身份证件等敏感数据分类分级和脱敏。
2. 薪酬计算、发放、调整必须幂等和审计。
3. 权限最小化：薪酬数据只对授权角色可见。
4. 组织、岗位、汇报关系变更保留历史版本。

### P1

- 考勤规则、排班、假期、加班、薪酬核算。
- 招聘、入职、转正、调岗、离职全流程。
- 绩效、培训、人才盘点。
- 个保法/GDPR 数据保留和删除策略。

### P2

- 人力成本分析、组织效能、人才预测。
- 多地区、多币种、多用工模式。

### 验收指标

- 薪酬数据无越权访问。
- 员工生命周期变更可追溯。
- 敏感数据导出受控并可审计。

## 8. OA

### 当前基础

- 报销审批、会议室冲突检测、公文、知识库版本、公告、日程。
- 12 个 Controller，测试不足。

### P0

1. 审批动作、意见、附件、授权、撤回全部审计。
2. 流程实例和业务单据绑定，防止只改业务状态不改流程。
3. 公文、知识库、公告按租户和组织做权限隔离。
4. 关键流程设置 SLA 和超时提醒。

### P1

- 公文流转、用印、档案、会议纪要。
- 知识库全文检索、权限继承、版本对比。
- 日程、任务、消息、待办统一入口。

### P2

- 智能审批、知识问答、文档生成。
- 跨组织协同和外部伙伴门户。

### 验收指标

- 审批记录不可篡改、可追溯。
- 业务状态与流程状态一致。
- 知识库越权访问为零。

## 9. TMS

### 当前基础

- 承运商、车辆、司机、运单、跟踪、运费、对账、GPS、车队成本利润。
- 9 个 Controller，业务闭环和测试仍需加强。

### P0

1. 运单、装卸、签收、回单、运费结算全链路状态机。
2. GPS 和司机信息按敏感数据处理，保留访问审计。
3. 运费计算和结算必须有幂等键。
4. 对账差异必须可解释、可处理、可追溯。

### P1

- 多计费模型、燃油附加、路桥、回单、异常费用。
- 车辆调度、装载、路径规划、承运商绩效。
- 运输可视化、电子回单、异常预警。

### P2

- VRP 求解、网络优化、碳排核算。
- 多式联运、跨境合规（如未来有真实需求）。

### 验收指标

- 运单到结算到对账可追溯。
- 重复结算不重复入账。
- GPS 访问有权限和审计。

## 10. 建议新增业务域

| 域 | 引入理由 | 前置条件 |
|---|---|---|
| SRM | 采购协同、供应商准入、绩效 | ERP 采购和 QMS 先稳定 |
| EAM | 设备台账、维修、备件 | MES 设备主数据和 TPM 先稳定 |
| PLM | 产品、BOM、ECN、工艺 | MDM 和 MES BOM 先统一 |
| BI | 指标、报表、驾驶舱 | 主数据和指标口径先统一 |
| IoT | 设备实时采集 | MES/SCADA 和边缘网关先落地 |
| CDP | 客户数据平台 | CRM 和隐私合规先达标 |
| ESG | 碳排、能耗、合规报告 | 数据采集和核算边界先定义 |

## 11. 路线优先级

1. P0：安全、库存、质量、工单、回款。
2. P1：ERP 财务闭环、WMS 策略、MES 设备、CRM 服务、TMS 结算。
3. P2：HR/OA 深化、BI、SRM、EAM、PLM。
4. P3：CDP、IoT、ESG 等按真实客户需求引入。

**原则：没有真实客户和合规需求时，不先做新域的复杂功能；先把已有八域的闭环做正确。**
