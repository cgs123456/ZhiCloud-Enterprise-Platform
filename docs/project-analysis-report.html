② 架构与分层

采用模块化单体（Modulith）：一个 reactor 内分 framework（16 个 starter） → 各业务 module → server 启动模块。模块间禁止直接 import service，一律走 *.api 包定义契约（普通接口或反向 SPI）。

分层约定（单模块内）

  • controller/* — REST 入口，写接口须带 @PreAuthorize
  • service/* — 业务（Impl 类），JaCoCo 门禁覆盖对象
  • dal/dataobject/* — MyBatis Plus DO（@TableName）
  • dal/mysql/* — Mapper
  • enums/* — 错误码与枚举（集中治理）
  • api/* — 对外契约（模块边界纪律）

④ AI 能力深度剖析（RAG / Multi-Agent / DataLake）
本节为源码实证（Explore 代理逐类核对）。标注 文件:行号。多处发现 README 与实际实现不符，详见第 ⑦ 章。

4.1 AI 主模块（248 java / 18 Controller）

  • 模型厂商：AiPlatformEnum 定义 21 个平台（国内 12 + 国外 9），由 AiModelFactoryImpl.getOrCreateChatModel() 按平台 switch 构建并带缓存。
  • 核心对话链路：AiChatMessageServiceImpl 用裸 ChatModel.call()/StreamingChatModel.stream()，未使用 ChatClient。ChatClient 仅出现在 chatmemory/nl2sql/predictive/workflow 等 6 个 service。
  • Tool 调用：18 个 @Tool 方法（Wms/Mes/Erp/Qms 业务工具 + PersonService），经 AiAutoConfiguration.toolCallbacks() 汇聚；ToolAccessInterceptor 做黑名单/白名单/二次确认。
  • 多轮会话：两条独立链路——归档链路落表 ai_chat_conversation/ai_chat_message；ChatMemory 链路存 Redis（短期 20 条、压缩阈值 30、TTL 7 天），且未实现 Spring AI 的 ChatMemory 接口。
  • MCP：引了 starter 但 mcp.server.enabled=false、client.enabled=false——协议未开启，实际生效的是进程内 ToolCallbacks.from() 直调。

4.2 AI-RAG（42 java / 4 Controller）

  • 链路：Tika 解析 → 自写 semanticChunk() 分块（非 TokenTextSplitter）→ BGE-base-zh ONNX 向量化 → PgVector（维度 768，表 airag_vector_store） → 检索 → RRF 融合 → 重排 → 生成 + 引用溯源。
  • 混合检索：向量 topK=10 + BM25 topK=10，RRF（K=60） 融合（fuseHybrid()）。BM25 用 Okapi（K1=1.5, B=0.75），CJK 按字切分。
  • Reranker：ONNX Cross-Encoder（DJL + ONNX Runtime），缺失时降级 SimpleReranker（TF-IDF）。开关 zhicloud.airag.reranker.enabled，fallback-to-simple 默认 true。
  • 评估：RagEvaluationServiceImpl 提供 Faithfulness / AnswerRelevancy / ContextPrecision / ContextRecall，四项均由 LLM 打分，落表 ai_rag_evaluation_log。

4.3 AI-MultiAgent（41 java / 3 Controller）

  • ReAct 主循环：ReActAgent.run()，结构化 ReActStep{thought,action,actionInput,observation,tokensUsed}，scratchpad 累积 Thought/Action/Observation，LLM 须返回严格 JSON；终止 action="Final Answer"。
  • Supervisor + Worker：SupervisorAgent 规划任务 + 汇总；AbstractWorkerAgent 基类 + 4 个角色（report-writer / sales / procurement / production）；WorkerAgentRegistry 注册；MultiAgentExecuteServiceImpl 编排并做拓扑白名单防越权。
  • 熔断参数（MultiAgentProperties）：步数 10 / Token 4000 / 超时 60s / 调用深度 5 / 限流 5 QPS / 重试 3 次 / 熔断器失败阈值 5。

4.4 DataLake（11 java）

  • 接入：经 Spring RestClient 调 Trino REST /v1/statement（Trino 不在编译期依赖内），分页上限 100。
  • 3 个 MCP 工具：datalake_list_tables / datalake_query_table / datalake_get_archive_status（后者为占位，返回 PENDING）。
  • SQL 注入防护：实际为 5 重（非空 / 危险字符正则 / 前缀白名单 SELECT|WITH / 18 个禁用关键字 / 点分标识符逐段校验），README 称"4 重"。

⑨ 结论与建议

总体判断

这是一个工程纪律相当扎实的企业级平台：模块化边界清晰、并发三件套统一、7 道 CI 门禁把安全/鉴权/错误码/事务/裸抛都防住了回归，前端类型安全达到 0 错误。业务覆盖广度（八大域 + AI 三件套）在国内开源/自研平台中属于第一梯队。

对外介绍的三条建议

  1. 业务价值优先：用"从采购到交付全链路打通 + 原生 AI 对话/编排"开场，技术名词（Spring Modulith、RRF、ReAct）一句话带过，被追问再展开。
  2. AI 模块口径收敛：RAG/Multi-Agent 表述为"需配置开启后生效的能力"，不要说默认开箱即用（规避 #4/#6 不一致）。
  3. 八大域对齐前端：对外讲"全栈打通"时，明确 OA/TMS/DataLake 前端页面尚未配套、FMS/IoT 等后端已禁用——避免被问"这个模块前端在哪"。

工程侧建议（按性价比排序）

  1. 高 修复 #4：补 application.yaml 的 zhicloud.airag.enabled 段，或把 @ConditionalOnProperty 改为 matchIfMissing=true，让 RAG 真能默认跑起来。
  2. 高 修复 #6：评估把主对话链路迁移到 ChatClient，使 RagAdvisor/PromptInjection/PiiMask 在主链路生效（安全与溯源收益大）。
  3. 中 修复 #7：给 BM25 路径的 Document 补 metadata，恢复引用溯源；或明确文档声明"混合检索下引用溯源仅向量路径可用"。
  4. 中 校正 README 第 4/6/7 章与代码偏差（分块实现、MCP 实际状态、防护重数）。
  5. 低 推进 Item C 覆盖率至 0.40、补齐 ERP/CRM/QMS/TMS 单测；决策 U-2/U-7/U-10。
